# Dataset Card — triage-router 意图分类数据

## 任务定义

四分类意图路由：给定用户输入，输出单个 JSON `{"intent": "<label>"}`。

| 标签 | 含义 | 路由目标 |
|------|------|----------|
| `interview_prep` | 面试准备 / 求职策略 | InterviewPrepSpecialist |
| `mock_interview` | 模拟面试 / 当场问答 | MockInterviewSpecialist |
| `resume_opt` | 简历优化 / 诊断改写 | ResumeOptSpecialist |
| `out_of_scope` | 与求职完全无关的输入 | 映射至 `interview_prep`（拒答层未实现） |

## 数据规模

| 集 | 条数 | 说明 |
|----|------|------|
| 训练集 | 1527 | 合成数据为主 + 定向补数，人工抽检 |
| 测试集 | 100 | 真实用户输入，人工标注，**冻结**，不再改动 |

## 构造方法

- 按意图分类法（`intent_taxonomy.md`）用模板 + LLM 合成种子数据
- 全部合成数据经人工审阅后才允许并入训练集
- 评测暴露错例后按错误类型分桶，定向补充同类样本，两轮迭代
- 训练 / 测试**严格隔离**：测试集来自真实语料，与训练分布不同源

## 标注与格式

每条样本为 ChatML 指令微调格式：

- **user** 消息 = `INSTR` 指令前缀 + 用户输入
- **assistant** 消息 = `{"intent": "<label>"}`（标签存于 `output` 字段，JSON 字符串）

## 已知噪声与局限

- 训练集中存在少量标注噪声样本（合成审阅漏网），已在评测错例分析中定位；刻意保留以衡量噪声上限，不静默清洗
- `out_of_scope` 与三类的边界（真实文本碎片、极短输入）是主要错误来源：Q4 模型 7 个错例中 6 个属于此类
- 测试集规模 100 条，±1 条即 1pp，小样本波动需注意

## 使用纪律

- **测试集冻结**：任何迭代不得针对测试集调数据或调 prompt
- 新增数据必须走「生成 → 人工审阅 → 合并」流程
- 基线对比必须使用对手最强形态（四分类完整 prompt），否则结论无效
